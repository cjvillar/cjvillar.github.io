Maker-Stack

Maker-Stack is built around projects and parts, not influencer posts.
January 1, 2026

Problem#

GitHub is for code, Instagram and Reddit are full of noise. There’s no dedicated place to share a build: the prototype stage, the components, and the steps to actually make it.

Solution#

Maker-Stack provides makers one place for everything: project pages, component lists, and a public feed to share/discover builds.

Links#

  • Live Site: View Project
  • GitHub: Source Code

Tech Stack#

  • Frontend: Django Templates + custom CSS
  • Backend: Django 6.0 (ORM, class-based views, AllAuth, tasks)
  • Database: PostgreSQL hosted on Railway
  • Media Storage: Cloudflare R2
  • Deployment: Docker + Gunicorn on Railway
  • CI: GitHub Actions

Preview (Parts List, Dark Mode)#

Challenges & Lessons Learned#

  • Django 6.0 has a lot of new additions. I used the built-in CSP to protect against XSS. Template partials cleaned up repetitive code. Background tasks handle populating the parts list data without breaching vendor API terms.
  • R2 + Django + Railway. Setting up Cloudflare with Railway was straightforward. The one mild annoyance was replacing my DNS provider’s nameservers with Cloudflare’s, but the added features made it worth the effort.
  • Test discipline matters from day one. I started the accounts app with good coverage. I’d bring that same rigor to the rest of the project apps from the start next time.

Future Improvements#

  • Add more distributors to live component pricing.
  • Expand social logins via AllAuth.
  • Project ranking for better discovery.

Takeaways#

  • Skills gained: Learned the latest Django offerings and how to release with Railway and Cloudflare R2.
  • Problems solved: I now have a platform I can share with anyone who wants to document and show off their hardware projects.
  • Why it matters: Maker-Stack keeps my Django skills current with real infrastructure decisions and a live service.
